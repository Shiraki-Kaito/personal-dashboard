# ノート編集の段階的な実装

## 実装済み：画面内の下書き

ノート本文の取得に成功した後、「編集用の下書きを作る」からダイアログを開きます。元のパス・コミットを表示し、Markdownを編集・コピー・`.draft.md`としてダウンロードできます。本文はHTMLとして実行しません。

GitHubには書き込みません。読み取り専用トークン・既存の本人認可・`*_L.md`の除外を維持します。下書きは画面のメモリーだけで保持し、閉じると消えます。未コピーの変更は閉じる前に確認し、ページ離脱にもブラウザー標準の警告を要求します。ただしOSによる終了やモバイルの強制終了では警告できないため、こまめにコピーまたはダウンロードしてください。自動保存・再起動後の復旧は未実装です。

コピーの成功とGitHubへの保存は区別します。ダウンロードの完了はブラウザーから確認できないため、開始しても破棄確認を解除しません。Windows専用WebView2アプリはダウンロードを無効にしているので、コピーを使うか通常のブラウザーで開いてください。

## 検証（2026-11-21）

全392テスト・ビルド成功。追加テストで、元本文の保持、編集後のコピー、遅いコピー完了後に新しい変更を未保存として扱うこと、UTF-8で256KiBの上限、空本文、ローカル限定名の拒否を確認。Workerテストで未認証の新規JSへのアクセスを拒否することも確認しました。実画面の編集操作・ダウンロード、本番デプロイは未実施です。

## 次に必要な実装

1. 下書きの永続化と復旧。保存先、元の版、取得範囲変更時の保護、バックアップを既存方式に合わせて設計する。
2. GitHubへの直接保存。保存前に最新の版を照合し、競合時は上書きを停止する。結果不明時は再取得・照合し、無条件に再送しない。
3. 本人による対象リポジトリだけの書き込み権限設定と、試験用ノートでの実保存検証。現在のトークンを勝手に変更・拡張しない。

この段階をノート編集全体の完成とは扱いません。
