# 定例の進捗報告

Driveの上部にある3つの報告ブロックから開きます。表示設定はチーム別ブロックの下、資料・期間・認可の設定は報告ダイアログの下にまとめています。手入力の進捗状態や期限を先に埋める必要はありません。旧手入力の保存内容は削除していません。

## 作成・保存

1. チーム定例／Organizer定例／全体定例を選びます。初期の報告者は白木海斗、対象は集客広報です。
2. 報告対象日、対象チーム、報告者を確認します。対象は現在取得しているDrive範囲内です。集客広報は配下全体、SNS・LP・コミュニティ連携・デザインはそれぞれのグループです。「全選択」は表示された登録チームすべてを指し、未接続の他チームまでは取得しません。
3. 下側の設定で参照資料・資料の用途・必要ならフォルダを選びます。初期候補は保存済みの参照設定、または取得済み一覧内の議事録・レポートです。候補の選択だけでは本文を読みません。
4. 「進捗報告を作成」を押します。選択した資料だけを読み取り、下書きと根拠を保存します。作成だけでは使用済みになりません。
5. 各チームの報告を編集・コピーできます。編集後は「下書きを保存」。実際に定例で使用したら、内容・不足情報の確認チェックを入れ、「使用済み確定版として保存」します。
6. 確定版は上書きできません。変更版が必要なら新しい下書きを作ります。前回比較は同じ種類・同じチームの使用済み確定版を優先し、チーム定例では報告者も照合します。

未保存の編集を破棄する操作には確認を出します。保存前の版を照合するため、別画面の変更を古いフォームで上書きしません。作成の結果が不明なら履歴を再取得します。同じ作成IDの再確認では資料を再取得・重複保存しません。保存の結果が不明な場合も、無条件には再送しません。

## 期間と比較

初期の対象期間は、読めた同じ定例の議事録または前回確定版の日付から報告日までです。確認できなければ報告日を含む直近7日間を仮設定して表示します。チームごとに前回日が異なればそれぞれの期間を使います。設定欄から明示的な期間へ変更できます。報告日より後の実績は含めません。

前回から残る同じ完了記載、複数資料の同じ記載を新しい実績として繰り返し並べません。新規の完了がなければその旨を示します。前回だけにあるNext Actionsの消失を、完了と推測しません。期限超過は確認事項へ分け、未完了を断定して再作業を催促しません。

資料の更新日時は、実施日として使いません。本文の明示日または議事録で報告された日を根拠として区別します。相対的な過去の表現、日付不明、同じ作業の状態の矛盾は確認事項です。同名ファイルは保存場所・更新日時・内容の根拠を表示し、名前だけで一方を現行版と断定しません。

## 書き分けと根拠

- チーム定例：本人の担当見出し、または本人と明示した表記・シートの担当者列に一致する作業です。本文に名前が出るだけでは本人の作業にしません。別名は設定欄で明示します。
- Organizer定例：対象チーム全体の成果・Next Actions・相談共有を整理します。共通議事録にチームの見出しがなければ他チームの実績を混ぜません。
- 全体定例：主な項目を最大4件ずつに絞ります。その他は根拠一覧に保持し、複数チームでは報告を分けます。

出力は「チーム名または報告者名」「完了」「Next Actions」、該当時だけ「相談・共有事項」です。通常は完了・Next Actionsそれぞれ最大6件、全体定例は最大4件を本文に出します。根拠は省略された項目も確認できます。

各項目で資料名・リンク、保存場所、議事録の日付・見出し・位置、資料更新日時、段階と判定、件数の区分、比較元と変更点を表示します。本人が編集した文章はその印を付け、生成時の根拠が編集内容まで証明するとは扱いません。

コミュニティ連携は候補・初回連絡・返信交渉・打ち合わせ予定・実施・連携確定・相互告知を区別します。団体名と段階実施日を読めるシートだけで、段階別の期間内件数・読めた範囲の累計を数えます。同一団体の反復連絡は重複しません。連絡数を連携確定数へ変換したり、段階間を合算したりしません。件数が不明な文面から数字を作りません。

## 読み取りと認可

既存のDrive接続と本人認可を再利用します。通常のDrive接続はメタデータ権限のままです。報告専用の認可経路だけで `documents.readonly` と `spreadsheets.readonly` を要求します。Google側の許可範囲は閲覧可能な全Docs・Sheetsですが、アプリの取得対象は、取得済みフォルダ内から画面で選択した資料だけです。Google Docs API・Google Sheets APIの有効化も必要です。APIが無効、利用制限、閲覧権限・認可の不足を区別して表示します。

取得はGETだけです。Drive・Docs・Sheetsへ書き込みません。本文全体を保存せず、生成文・抽出した根拠・確認事項・参照元・生成条件・版をSQLite Durable Objectへ保存します。秘密値は応答やバックアップへ含めません。AI APIは使わずルールで解析します。

## 現行の制約

- 一度に1〜12資料。フォルダを選んで上限を超えた場合は、先頭だけ読んで全件取得扱いにせず停止します。
- Docsは日付・見出し・リスト階層に対応します。表の列関係は未対応のため、表内の断片を実績へ変換せず不足として示します。
- Sheetsは最初の10行以内の列見出しを使います。タスク／作業／内容／団体名、状態、担当者、完了日・段階実施日、期限などの明示列が対象です。未知の列や曖昧な書式は推測しません。
- Sheetsは最大10シート、各1000行・32列、返却されたデータの合計32000セル。空白を含むシートの確保領域は合算せず、末尾の空行・空列を省いたAPI応答を検証します。行列を絞った場合は未取得範囲を表示します。Docs・Sheetsの応答は各2MiB、Docsの解析は5000段落・20万文字までです。
- PDF、Officeファイル、画像の本文解析は未対応です。選んだ場合はその資料を未取得として表示します。
- 言い換えを含むすべての同一案件や、自由な日本語の意味を完全には判別できません。本文を根拠に残し、読めない・曖昧な情報を完了や件数に補完しない方針です。コピー前の確認が必要です。
- 通常一覧は24件、アーカイブを含め96件、報告1件は2MiBまでです。96KiB単位に分割し、本文と索引を同一トランザクションで保存します。上限時は古い報告を削除せず停止します。これらはアプリ側の上限です。

[Docs取得API](https://developers.google.com/workspace/docs/api/reference/rest/v1/documents/get) · [Sheets取得API](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/get) · [Sheetsの権限](https://developers.google.com/workspace/sheets/api/scopes)

Sheets APIの読み取りは1分あたりプロジェクト300回・ユーザー60回の制限があります。利用条件・費用は[公式の使用制限](https://developers.google.com/workspace/sheets/api/limits)を確認してください。アプリ側のセル数・資料数の上限はAPI自体の制限とは別です。

## 履歴の整理・バックアップ

「保存した報告を開く」で履歴を選びます。アーカイブは通常一覧から隠すだけで、本文・確定状態・前回比較への利用を保持します。「アーカイブ済みも表示」から戻せます。確定版の本文は編集できません。

バックアップは全履歴、または表示中の1件を選べます。上限は16MiBで、一括出力できない場合も1件ずつ保存できます。報告本文・根拠を含むため、公開リポジトリへ入れないでください。接続資格情報や未保存の編集は含みません。

復元はファイルを選択し、件数・既存報告との重複を確認してから実行します。同じDrive範囲のファイルだけを受け付け、既存の同じIDを上書きしません。確認後に履歴やファイルが変わった場合は停止します。失敗時は部分復元を残さず、結果不明の場合は履歴を再取得してから確認します。

2026-11-19、本番でDocs・Sheetsの2資料を取得し、Organizer報告の下書き保存・履歴再取得・本文一致を確認しました。新しい報告APIの未認証アクセスは401で拒否されました。

架空データのブラウザー操作で、重複復元の停止、新規復元の確認画面と履歴追加、確定版の編集拒否、次回報告が前回確定版を比較元にすることを確認しました。通常履歴24件到達後にアーカイブして25件目を作成でき、満杯の通常一覧への復帰を拒否する回帰テストもあります。

768px幅では定例カード3列、320px・390px幅では横はみ出しなし。384×300の表示領域でも縦スクロールで履歴選択できました。加えてWindows Chromeのメニューで200%を確認し、実際の拡大状態でDriveのカードから報告ダイアログを開き、縦スクロールで入力欄・作成ボタンへ移動して閉じられることを確認しました。実資料の再生成や保存は行わず、終了後は元の100%へ戻しました。

本人確認により、実際の定例に使用済みの報告はまだありません。本番の下書きを試験のために使用済みへ変更していません。実運用の確定版比較は初回利用後に確認します。ローカル試験を実サービスの検証済みとは扱いません。
