personal-dashboard プライバシーポリシー

更新日：2026年11月16日。本アプリは管理者本人専用の個人ダッシュボードです。第三者への利用提供は行いません。

取得する情報と利用目的

GitHubの本人識別情報でログインを認可し、設定済みGitHub Projectsのタスク情報を取得します。状態・期限は本人の明示操作で更新します。Google Driveは認可されたアカウントのメタデータ閲覧権限を使用し、設定したフォルダと通常のサブフォルダ内のファイル名・識別子・種類・保存場所・作成更新日時を取得します。通常の更新一覧では本文を取得しません。

定例の進捗報告は、本人が選択した取得済みDriveフォルダ内の資料を最大12件読み、チーム定例・Organizer定例・全体定例の下書きを作ります。Google DocsとSheetsの本文取得には追加の読み取り認可を使います。Google側の権限範囲は閲覧可能な全Googleドキュメント・スプレッドシートですが、アプリの取得対象は画面で選択した資料・フォルダ内だけです。編集・送信・元資料への転記は行いません。本文全体を恒久保存せず、抽出した項目・根拠の抜粋・参照元と更新日時・対象期間・生成文・本人の編集・確定状態をサーバーへ保存します。生成履歴は最大24件で、使用済み確定版は上書きせず前回比較に用います。旧手入力記録も削除しません。新しい生成履歴は現行の手動バックアップには含まれません。AI APIや第三者の生成サービスへ送信せず、日付や完了が不明・矛盾・読めない形式の情報は確認事項として示します。

取得情報は、一覧の表示、同期の照合、未同期操作の復旧、未確認変更の表示に使用します。AIの学習や広告に使用せず、第三者への販売は行いません。

メール・カレンダーは本人が追加認可した最大5アカウントについて、直近14日のメールを1回20件ずつ、新着100件まで取得します。続きがある場合、就活・学校の件名、学校ドメイン、Gmailの重要マーク、本人設定の優先送信者・語句による検索をGoogleへ送り、重要候補を別枠100件まで取得します。重複を除く保存は各接続最大200件です。検索とアプリ内の判定は一致せず、検索枠の上限や検索に変換できない設定による未取得も表示します。重要メールの全件取得は保証しません。毎時の自動取得は接続・ページごとに分割し、前の完全な一覧を最後まで保持してから更新します。就活・学校関係の語句で重要度を判定し、通常表示を絞りますが、判定対象の取得済みメールは全件一覧にも残します。表示名は40文字までアカウントとは別に保存します。件名・差出人・受信日時・本文を予定候補の抽出に使用し、抜粋と抽出結果を保存します。添付ファイルは取得しません。本文が大きい場合は解析量を制限し、本文の一部だけを解析した印を保存して原文確認を表示します。通常はプレーン本文を優先し、本文を参照できない場合はGmailの抜粋で補います。各アカウントのメインカレンダーから候補時間帯の予定を読み、重複・時間競合を照合します。また、毎時の自動取得と本人の「予定を更新」操作で今日を含む7日間の予定を取得し、予定名・日時・場所・識別子・元サービスへのリンクを一覧用に保存します。上限は各アカウント500件で、全ページを取得できなければ前の完全な一覧を保持して警告します。登録は本人が予定名・日時・場所・登録先を確認した場合だけ行います。メールの送信・削除・既読変更や招待は行いません。

メール取得履歴は各接続の直近72回について開始・完了時刻、取得元、件数、ページ数、結果・エラー分類を保存し、件名・本文・資格情報は履歴へ含めません。メールの取得一覧は次の正常な取得で置き換え、取得失敗時は保持します。予定の登録結果不明・成功の操作記録は復旧と二重登録防止のためサーバーに保持します。メール本文の全文を恒久保存せず、本文抜粋は1通1600文字までです。手動バックアップv2には取得済みメールの抜粋・候補・確認記録・予定登録記録・表示名・重要判定を含めます。資格情報・セッション・認可途中の状態・取得履歴・診断履歴・再取得できる直近予定一覧のキャッシュは含めません。バックアップには私的な情報が含まれるため、本人が安全に保管します。

Slack連携（現行版では保留中・通常画面は非表示）

本人が専用Slackアプリを認可した最大5ワークスペースについて、Botが参加し、サイトで追加した各最大5チャンネルを読み取ります。公開チャンネルはchannels:read・channels:history、非公開を選ぶ場合はgroups:read・groups:historyを使います。Slackへの投稿・招待・既読変更は行いません。DM・グループDMは初期対象外です。

直近7日の投稿を1ページ15件・最大10ページずつ毎時取得し、投稿本文（6000文字まで）・送信者ID・投稿時刻・返信件数・添付件数・元サービスのリンクを保存します。スレッド返信全文・添付本文・ユーザープロフィールは取得せず、AI処理・学習・広告用途にも使いません。取得上限やSlackプランによる履歴制限は表示します。確認済み操作はアプリ内だけの記録で、Slackの既読状態は変えません。

専用アプリのClient ID・Client Secret・接続トークンは、本人限定の設定APIからCloudflareのサーバー保存領域へ登録できます。秘密値は取得APIに含めず、再表示しません。接続停止は対象ワークスペースのトークンを破棄し、取得を止めます。チャンネル設定・投稿キャッシュ・確認記録は保持し、Slack側の認可取消とは区別します。次の取得成功で投稿キャッシュを更新し、失敗時は前回の一覧を保持します。アプリ内のSlack確認記録は次の確認操作で30日より古い分を整理します。現行の手動バックアップv2にはSlack情報は含まれません。

GitHub上のノート

本人がサイトで指定した1リポジトリ・対象フォルダ以下のMarkdownを読み取り専用で表示します。非公開の場合は本人が専用Fine-grained tokenを非表示欄から登録します。トークンはサーバー保存領域にのみ保持し、取得API・バックアップに返しません。公開の場合は認証情報を付けず取得します。GitHubのツリー応答には対象内のファイル名等が含まれますが、*_L.md（大文字小文字を区別しない）に該当するパスは一覧保存・ブラウザー送信から除外し、本文APIを呼び出しません。アーカイブ全体を取得しません。

ノートのパス・識別子・サイズと選択コミットを一覧として保存し、本文は本人が選択した時だけ読み、サーバーへ恒久保存しません。Markdown原文を表示し、埋め込み画像・HTML・スクリプトは読み込みません。本文に書かれたローカル限定ノートへの言及や転載内容まで自動判別するものではありません。一覧は毎時・画面を開いた際の必要な更新・本人の手動操作で取得し、本文は定期取得しません。取得失敗時は前回の一覧を保持します。接続削除は本アプリの設定・資格情報・一覧を削除しますが、GitHub上のファイルやトークンの認可そのものは削除しません。現行の手動バックアップにノート情報は含みません。

保存した分割案件の管理

メールが取得一覧やホームに出ていない場合も、保存した分割案件の名前変更と分類解除ができます。保存分類の通数、取得済みメール数、ホーム表示数を区別して表示します。改名は同じ分割先を持つ全アカウントの名前と対応記録のラベルを同時に更新し、対応状態・メモ・再表示日・対応状況の保存時刻は維持します。

分類解除は対象案件の保存済みメールIDの手動分類だけを外します。メールや予定の削除・既読変更は行わず、分割側の対応記録とメモは履歴に保持します。自動のまとめに戻る側は未対応にします。操作前に対象の確認を求め、分類・案内・対応記録が変更された場合は上書きせず再取得へ誘導します。応答が不明なときも自動再送しません。

案件の手動分割

ホームの関連メールから宛先ごとにメールを選び、100文字までの名前を付けて別案件に分類できます。同じ元の関連候補から分けた既存案件にも移せます。案件ごとに提案・日時・対応状態を管理し、メールの既読・削除・送信・予定やGitHub Projectsは変更しません。新着メールは自動で分割先へ入れず、元の関連候補に表示します。

アカウントごとに自身のメールID、分割先の識別子・名前、元のまとめの照合値、分類の版を保存します。本文や他アカウントの識別子は分類記録へ複製しません。各接続1000通・512KiBまでです。分類変更で構成が変わる案件は未対応に戻し、別案件の状態は維持します。自動のまとめ方に戻す場合は取得範囲外を含む同じ分割先の分類を戻し、分割側の対応記録は履歴に保ちます。キャッシュ整理・接続停止では分類を保持し、バックアップv2へ含めます。完全削除では対象アカウントの分類だけを削除します。

案件の対応状況

ホームの関連メール候補を案件として、本人確認後に未対応・保留・対応済み、メモ（200文字まで）、任意の再表示日をアカウントごとに保存します。件名の組織名などでまとめるため、別案件が混ざる場合があります。保存時に対象の関連メールと宛先を確認してください。元メールの既読・削除・予定は変更しません。新しい関連メールや確定日時の変更で以前の記録が適用できなくなった場合は未対応に戻し、保留の再表示日は日本時間0時に判定します。登録結果が未確認の予定は状態変更で隠しません。

案件ラベル・状態・メモ・再表示日・保存時刻・版と元案内の照合値を保存し、メール本文や他アカウントの識別子は案件記録へ含めません。各アカウント1000件・512KiBまでとし、上限超過時は保存を拒否して既存記録を保持します。キャッシュ整理・接続停止では保持し、メールが取得範囲外でも保存記録を一覧で確認できます。未対応に戻しても古い画面の再保存防止のため版を保持します。バックアップv2へ記録を含め、アカウントの完全削除ではそのアカウントの案件記録だけを削除します。

重要メールの本人設定

アカウントごとに優先／除外する送信者・語句をサーバーへ保存できます。各欄20件まで、語句は100文字までです。送信者はメールアドレスまたはドメインの完全一致、語句は取得済み件名・本文抜粋の文字列一致で、除外を優先します。送信者表記の真正性やメールの安全性を保証しません。設定前のプレビューは取得済みメールだけを使い、外部APIへの追加送信は行いません。優先設定のうち安全に変換できる送信者・語句は定期取得時のGmail検索にも利用します。除外条件は検索へ送らず、取得後にアプリで判定します。設定はホームと一覧の分類に利用し、元メール・Googleの既読状態・確認記録・予定登録には変更を加えません。除外したメールも取得済み全件一覧に残ります。手動バックアップに設定を含め、接続停止とキャッシュ整理では保持します。本アプリからのアカウント完全削除時に対象の設定も削除します。

Windowsの独立ウィンドウ

Chrome／Edgeのアプリ追加機能を使い、同じ本人専用サイトを独立した通常ウィンドウで開けます。追加用の一般的なアプリ名・アイコン・表示設定だけを未ログインでも取得できます。データAPI・画面の実行用JavaScriptは本人認可を維持します。追加によって外部サービスの権限を増やしません。端末への独自の本文保存・オフライン編集・Service Workerによるキャッシュ・自動起動・通知権限は追加していません。インストールの操作はブラウザーが処理し、アプリ側にインストール済みフラグを永続保存しません。ブラウザー側の通常の履歴・アプリ管理情報はそのブラウザーの設定に従います。

保存と外部サービス

アプリはCloudflare WorkersとDurable Objectsで動作します。外部サービスのアクセストークン等の資格情報、取得したメタデータ、同期状態、未確認変更はサーバー側に保存します。秘密値をブラウザーへ配布しません。ブラウザーにはログイン用のSecure・HttpOnly Cookieを使用します。通信先はCloudflare、GitHub、Google、接続した場合のSlackです。解析・広告用のトラッカーは導入していません。

保存期間と確認済み操作

メールの「確認済み・対応不要」は、元メールのIDと確認時刻をアプリ内に保存します。Gmailの既読・ラベル・本文には変更を加えません。次の確認操作時に14日より古い確認記録を整理し、1アカウント5000件を上限とします。予定候補なしと判定したメールも取得済み全件一覧から確認できます。

直近の成功一覧は取得に失敗しても保持し、次の成功取得で更新します。未確認変更は本人が確認済みにするまで保持します。確認済み操作はアプリ内の未確認一覧だけを変更し、Driveのファイルを変更・削除しません。未同期のGitHub操作は照合完了または明示的な破棄まで保持します。操作記録の完全な履歴を保存するものではありません。

連携解除と削除

GitHubのログアウトでアプリのGitHubセッションと保存トークンを破棄します。Google連携とキャッシュはログアウト後も保持します。GitHubとGoogleのアカウント設定で本アプリの認可を取り消せます。認可の取消は保存済みキャッシュを自動削除しません。同じGoogle OAuthアプリへの認可取消は、そのGoogleアカウントの他の連携にも影響する場合があります。保存データの完全な削除は管理者が本アプリ専用のサーバー保存領域で行います。Driveの再接続は同一アカウントを照合して一覧と未確認変更を保持します。

Googleユーザーデータ

Google APIから受け取った情報の使用と他のアプリへの転送は、限定的使用の要件を含むGoogle API Services User Data Policyに従います。アプリの管理・連絡先は専用Google Cloudプロジェクトのユーザーサポート情報で管理します。
